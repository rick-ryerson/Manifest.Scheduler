## Docker

The application is containerised with a multi-stage `Dockerfile` (`src/Manifest.Scheduler.Api/Dockerfile`, generated by Visual Studio's container tooling) and orchestrated via `docker-compose.yml` + `docker-compose.override.yml` in the repo root. `docker-compose.dcproj` registers the compose files as a project node in `Manifest.Scheduler.sln` so Solution Explorer and F5 debugging can drive them directly — this is why `dotnet build`/`dotnet test` must target `Manifest.Scheduler.sln` explicitly rather than relying on directory auto-detection (see Commands above).

```bash
# Build images and start all services (API + PostgreSQL) in the foreground
docker-compose up --build

# Run in the background
docker-compose up --build -d

# Tail logs when running detached
docker-compose logs -f api

# Stop and remove containers (data volume is preserved)
docker-compose down

# Stop and remove containers AND the data volume (full reset)
docker-compose down -v
```

### Services

| Service | Container port | Host port | Notes |
|---------|---------------|-----------|-------|
| `api`   | 8080          | 8080      | Swagger UI at `http://localhost:8080/swagger` |
| `db`    | 5432          | 5432      | PostgreSQL 16 (user: `scheduler`, db: `ManifestScheduler`) |

On first start the API automatically applies any pending EF Core migrations via `Database.Migrate()` in `Program.cs`. The API waits for the database to pass its health-check before starting (configured via `depends_on: condition: service_healthy`).

### Environment variables

The `docker-compose.yml` overrides the connection string for the `api` service using the environment variable convention:

```
ConnectionStrings__DefaultConnection=Host=db;Port=5432;Database=ManifestScheduler;Username=scheduler;Password=scheduler_pass
```

To supply secrets outside of Compose, set the variable in your shell or a `.env` file before running `docker-compose up`.

## Architecture

This is a .NET 8 solution with Clean Architecture layering:

- **Domain** (`src/Manifest.Scheduler.Domain`) — entities, value objects, domain interfaces. No dependencies on other projects.
- **Infrastructure** (`src/Manifest.Scheduler.Infrastructure`) — implements domain interfaces; handles persistence, external services, etc. References Domain.
- **Api** (`src/Manifest.Scheduler.Api`) — ASP.NET Core Web API with Swagger/OpenAPI. References Infrastructure (and transitively Domain).
- **Tests** (`tests/Manifest.Scheduler.Tests`) — xUnit test project. References all three source projects.

Dependency flow: `Api → Infrastructure → Domain`

## Domain model

The domain is namespaced `GalacticSenate` (`src/Manifest.Scheduler.Domain/GalacticSenate`) and models parties (people and organizations) and the roles they hold.

- **`Party`** (abstract) — base identity: `Id` (Guid), `TenantId` (Guid), `CreatedAt` (UTC).
- **`Person : Party`** — adds `FirstName`, `LastName`.
- **`Organization : Party`** — adds `Name`.
- **`PartyRole`** — `Id`, `TenantId`, `PartyId`, `Party` (nav), `RoleType` (`PartyRoleType` enum: `Student`, `Instructor`, `Administrator`, `Observer`), `AssignedAt`.
- **`IMustHaveTenant`** (`Domain/Common`) — `Guid TenantId { get; set; }`. Any entity implementing this is auto-scoped by the EF Core global query filter (see below). `ICurrentTenantService.CurrentTenantId` supplies the tenant.

Repository interfaces (`Domain/GalacticSenate/Repositories`) are Domain-only contracts — `IRepository<T>`, `IPartyRepository`, `IPersonRepository`, `IOrganizationRepository`, `IPartyRoleRepository` — implemented in Infrastructure.

### Multi-tenancy

Every write must resolve a tenant. `ICurrentTenantService` (implemented by `CurrentTenantService` in Infrastructure) reads the **`X-Tenant-Id`** request header. Services call a shared `CurrentTenantIdOrThrow()` helper and throw `InvalidOperationException` if the header is missing or unparsable — callers must always send `X-Tenant-Id` on every request.

### Persistence (TPT)

`ApplicationDbContext` (`Infrastructure/Persistence`) maps `Party`/`Person`/`Organization` using **table-per-type**: `Parties`, `People`, `Organizations` (shared PK across the hierarchy), plus `PartyRoles`. PostgreSQL via Npgsql — identifiers are case-sensitive and quoted (`"People"`, not `people`).

The global query filter is applied only to the **root** entity type in each `IMustHaveTenant` hierarchy (EF Core disallows filters on non-root TPT types), filtering `TenantId == (CurrentTenantId ?? Guid.Empty)`. Because `Party` is abstract, assigning a subtype to an existing Party row (e.g. `AssignPersonToPartyAsync`) uses a raw parameterized `INSERT INTO "People" (...)` rather than `DbSet.Add`, since the `Parties` row already exists and only the subtype table needs a row.

## API reference

Single controller, `PartyController` (`src/Manifest.Scheduler.Api/Controllers`), base route `api/Party`. All requests require an `X-Tenant-Id` header.

| Method | Route | Purpose |
|--------|-------|---------|
| `POST` | `/api/Party/people` | Create a Person (inserts `Parties` + `People` in one transaction) |
| `POST` | `/api/Party/people/{partyId}/assign` | Assign the Person subtype to an existing Party |
| `POST` | `/api/Party/organizations` | Create an Organization (inserts `Parties` + `Organizations`) |
| `POST` | `/api/Party/organizations/{partyId}/assign` | Assign the Organization subtype to an existing Party |
| `POST` | `/api/Party/{partyId}/roles` | Assign a `PartyRoleType` role to a Party |
| `GET` | `/api/Party/{partyId}/roles` | List roles for a Party |
| `DELETE` | `/api/Party/roles/{roleId}` | Remove a role assignment |

Errors are returned as RFC 7807 `ProblemDetails`: `InvalidOperationException` messages containing "does not exist" map to 404, other `InvalidOperationException`s map to 400, unhandled exceptions map to 500 via the global `UseExceptionHandler()`.

## Tests

`tests/Manifest.Scheduler.Tests` has two kinds of coverage:

- **`Infrastructure/Persistence/ApplicationDbContextTests.cs`** — unit tests against the EF Core InMemory provider, verifying the global tenant query filter isolates rows between tenants.
- **`Infrastructure/Services/ServiceIntegrationTests.cs`** — integration tests against a real PostgreSQL container via **Testcontainers** (`postgres:16-alpine`). Uses `[SkippableFact]`/`Skip.IfNot` so the suite skips gracefully (rather than failing) when Docker isn't running. Covers TPT dual-table inserts, tenant stamping, cross-tenant isolation, and assign-to-nonexistent/wrong-tenant-party error paths.
